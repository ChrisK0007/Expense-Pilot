Expense Pilot 1.0.6 promotes the complete tested beta.1–beta.19 series to the stable Docker channel.

- **Simpler deductions:** recognised equipment purchases receive a suggested treatment using their date, cost, use split and saved annual rules. Import existing depreciation schedules, retain accountant-entered figures, and attach receipts after a deduction is created. Advanced adjustments stay available; estimates remain subject to accountant review.
- **Refined invoicing:** full-page invoice and quote editing, recoverable drafts, actual PDF previews, Classic/Modern/Compact layouts, brand and font controls, quantity types and optional supporting attachments. Correct and reissue unpaid invoices while retaining earlier revisions; paid invoices stay locked.
- **Email control:** paste formatted signatures with linked images, choose whether to receive a copy for each send, and configure owner notification preferences.
- **Cleaner daily work:** focused notification bell, direct navigation, topic-based settings, calendar or financial-year dashboard comparisons, multiple workspace filters, renamed categories and sortable expense tables. Date pickers work in Safari, and invoice due dates follow payment terms until manually changed.
- **Documents and matching:** background document reading with retry recovery, supported local payslip extraction, preserved originals and automatic matching of clear bank/expense pairs. Imported income still requires review.
- **WFH and reporting:** fixed-rate home-office diaries, reviewed logbook imports, supporting tax documents, branded WFH and mileage PDFs, and verified nightly local backups.
- **Access and reliability:** tax agents see selected financial years and tax evidence, with limited optional editing and permanent account removal. Add new-IP sign-in alerts, the updated SQLite runtime and audited dependencies. Matching application and dependency source archives remain available in the app and below.

Install `ghcr.io/chrisk0007/expense-pilot:1.0.6` or use the moving stable tag `latest`. The image supports Linux AMD64; the optional iPhone app is separately versioned and is not updated here.

**Existing installations:** back up the complete `/data` directory, update the image and preserve the same data mapping and deployment settings. Startup applies migrations m020–m028 when upgrading from stable 1.0.5. A beta.19 installation already has these migrations; moving it to stable adds none. Never share a data directory between running containers. Rollback requires the previous image and its matching pre-update backup.

**Tax-agent sharing:** after upgrading from stable 1.0.5, select the financial years to share with each existing tax agent before they resume work. Accounts default to no shared years; the owner's records remain intact.

On Unraid, use **Docker → Check for Updates → Update**, then refresh the browser and confirm **1.0.6** in Settings. A container currently following `:beta` must be changed to `:latest` or `:1.0.6` to follow this stable release, keeping its existing appdata mapping.
