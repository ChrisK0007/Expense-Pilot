Open Settings to add business branding and SMTP details, then Clients to create billing contacts. Create a draft invoice or quote, inspect the PDF, and use Issue & email to review the recipient and message before sending. Record payments when received. Quotes can convert to invoices; billable time can create an invoice; repeating schedules generate drafts for your review.

SMTP passwords are encrypted; preserve the data folder and session.key in backups. Financial records and receipt files remain unencrypted. This version supports SMTP with TLS, not OAuth mailbox sign-in, live bank feeds, card checkout, BAS or income-tax estimates.

1. Manual-build installation alternative

Extract the expense-pilot folder from the ZIP to /mnt/user/appdata/expense-pilot. The Dockerfile and app.py should be directly inside that directory.

Open the Unraid terminal:

cd /mnt/user/appdata/expense-pilot
bash prepare.sh
docker build -t expense-pilot:0.2.0 .

The preparation script creates a unique setup token in .env and sets data ownership to Unraid's nobody/users (99:100). Existing .env and data are preserved. Image building needs internet access to Docker Hub, Debian packages and PyPI.

Run the included integration tests using the image and a temporary data directory:

docker run --rm --entrypoint python \
  -v /mnt/user/appdata/expense-pilot/tests:/app/tests:ro \
  expense-pilot:0.2.0 -m unittest discover -s tests -v

The tests use a temporary database inside the test container; they do not touch your live data.

Start with Docker Compose

If Docker Compose is installed:

docker compose up -d

Or start with standard Docker

Use one method only. The following needs no Compose plugin:

docker run -d \
  --name expense-pilot \
  --restart unless-stopped \
  --user 99:100 \
  --env-file /mnt/user/appdata/expense-pilot/.env \
  -e DATA_DIR=/data \
  -p 8788:8788 \
  -v /mnt/user/appdata/expense-pilot/data:/data \
  --read-only \
  --tmpfs /tmp:rw,size=256m,mode=1777 \
  --cap-drop ALL \
  --security-opt no-new-privileges:true \
  --memory 1g \
  expense-pilot:0.2.0

Open http://YOUR-UNRAID-IP:8788. Copy the SETUP_TOKEN value from the .env file into the first-run screen, then create your owner account. No default username or password is supplied. The setup endpoint locks after the owner is created.

The container's restart policy brings it back after a server reboot. A container created from the terminal will appear on Unraid's Docker page but will not have a saved Unraid GUI template. You can manage it with the commands here, or use Add Container with repository expense-pilot:0.2.0, port 8788, the /data mapping and environment variables above.

2. Add your bank accounts

In Bank accounts → Add account, create separate labels for CommBank, Macquarie and American Express. Only the owner can see bank-account settings or import statements. Account labels do not connect to the bank and no banking credentials are collected.

  1. Export transactions as UTF-8 CSV from your bank. The file needs a header row; remove report preambles first if necessary.
  2. Select the matching account, choose Import CSV and inspect the sample rows.
  3. Map date, description and amount/debit columns. Choose the exact date format shown in your file.
  4. Set the debit sign: negative for a signed column with negative purchases; positive for a debit-only column or a card export with positive charges.
  5. Confirm the imported count. Credits and zero-value rows are skipped.
  6. Review imported rows in Expenses. Each starts as Personal / To review / 0% use. Reclassify eligible records as Employment or Business and set the use percentage.
Transfers and card repayments can look like purchases in a debit export. Keep these Personal with 0% use, or delete them. Importing both a bank repayment and individual Amex purchases must not result in counting both as business expenses.

Duplicate detection compares account, date, exact description, amount and occurrence number. Reimporting an identical file is safe. Overlapping exports containing different subsets of identical same-day purchases can be ambiguous; review the results. There is no live feed, bank-balance reconciliation, OFX import or automatic transaction reconciliation in v0.3.0.

Supported mapping formats: DD/MM/YYYY, DD/MM/YY, YYYY-MM-DD and MM/DD/YYYY; delimiters comma, semicolon or tab; maximum 5,000 rows and 12 MB per upload. All amounts are AUD. Foreign-currency conversion must be entered manually using your settled AUD amount or other appropriate documented conversion.

3. Capture receipts with AI

Open Add expense, upload a JPEG, PNG, WebP or PDF, and optionally select Read with AI. Uploading alone does not send data to the AI endpoint. Extracted fields stay in the open form until you save them.

Edit .env to point at an existing Ollama server:

OLLAMA_URL=http://YOUR-UNRAID-IP:YOUR-OLLAMA-PORT
OLLAMA_MODEL=YOUR-INSTALLED-VISION-MODEL

Use the address accessible from inside the container. localhost would refer to the expense container itself. Choose an installed model that accepts images for photos and scanned PDFs; a text-only model can only process extracted text from text-based PDFs. This app does not install or download an AI model.

Recreate the container after changing .env. With Compose:

docker compose up -d --force-recreate

With plain Docker, stop and remove only the container, then rerun the start command above. The /data folder stays intact. A simple restart does not reread --env-file settings.

Text PDFs send extracted text. Scanned PDFs render pages to images. PDFs must be unencrypted and contain no more than eight pages. The upload limit is 12 MB. Extraction uses Ollama's /api/chat endpoint with a JSON response; it does not include OpenAI API support in this version. A configured endpoint is not a tested connection; use a test receipt to confirm the model works.

AI results can be wrong. Check the merchant, date, amount, currency and category. For detected non-AUD currencies the amount is not filled automatically. The original receipt is retained, while uploaded images are normalised to JPEG. AI does not approve deductions or calculate GST.

4. Track overnight meals

  1. Create a trip under Overnight trips, with location, departure/return dates, purpose and Employment or Business scope.
  2. Record any allowance received separately on the trip. The allowance field is the total received for this trip, not a rate calculation.
  3. Add each meal as an expense, select category Meals, select the trip and choose Breakfast, Lunch, Dinner or Incidentals.
  4. Attach evidence and add notes. Mark reimbursed items so their allocated amount is zero.

Expense dates must fall within the trip, and the person and scope must match. Nights are calculated as the difference between the two dates. Trip meal totals show actual recorded spend, including reimbursed meals; the expense allocation excludes reimbursements. Allowances are not automatically subtracted from expenses and no ATO reasonable-amount rate or receipt exemption is inferred.

You can edit or delete trips. A trip cannot be deleted while expenses remain linked, or changed so that linked expenses no longer match. This prevents accidental orphaned records.

5. Control access

Configure SMTP under Settings → Email delivery & templates, then set your Expense Pilot login address under Account invitations. Add a person under People & access to email a generated temporary password. The password expires after 48 hours and must be changed before records can be opened. The People list shows delivery and 2FA status and lets the owner resend pending invitations.

Each person can enable authenticator-based two-factor authentication in Settings. Scan the QR code, confirm a six-digit code and save the ten one-use recovery codes. Existing accounts keep their passwords. Read-only tax agents can manage their own password and 2FA.

Home base preferences now use a built-in Australian suburb search and a configurable 50 km default radius. Typed dates automatically normalise to DD/MM/YYYY; invalid dates remain rejected. See README.md for current release details.

6. Reports and backups

Choose a financial year or date range in Tax reports, then download the CSV. The owner export contains all matching records, including personal and unreviewed entries; the tax-agent export contains only the explicitly shared set. The export labels scope, percentage, reimbursement, review state and receipt IDs. Download receipts individually from the expense. There is no combined tax-agent ZIP in this version.

Allocated amount is amount paid × use percentage, rounded to cents; personal or reimbursed entries allocate zero. Refunds can be recorded as negative expenses. This is an expense organiser, not a complete income ledger, BAS calculator, payroll system, tax return or determination of tax deductibility.

Run a consistent backup to a separate private folder:

bash backup.sh /mnt/user/backups/expense-pilot

The helper stops the container briefly, archives the SQLite database, receipt files, session key and .env, then restarts it. Store backups privately; they contain financial information and configuration. SMTP passwords are encrypted using the backed-up session key; financial records and receipts are not encrypted at rest. Protect the Unraid share and backup destination accordingly.

To restore, stop the container, keep a separate copy of current data, extract the backup into the installation folder so it replaces data/ and .env, restore ownership with chown -R 99:100 data, then recreate the container with the restored environment. Keep app and data versions matched.

7. Remote access, updates and troubleshooting

For remote staff or tax-agent access, use HTTPS through your existing reverse proxy/tunnel and set COOKIE_SECURE=true before recreating the container. Keep the app login enabled. Avoid exposing the HTTP port directly to the internet. Initial LAN HTTP setup requires COOKIE_SECURE=false.

docker logs --tail 100 expense-pilot
docker inspect --format '{{.State.Health.Status}}' expense-pilot

Logs go to Docker's container log and include request paths and status codes. The activity screen records application mutations. Receipt content and passwords are not intentionally logged. Health status checks that the application responds; it does not verify the AI service.

For an update, back up first. Replace source files without overwriting .env or data, rebuild the image and recreate the container. Preserve /data for all updates. Do not delete the appdata folder.

If the first screen is unavailable, check port 8788, the volume mapping, directory ownership, container logs and image build output. If an import fails, verify the selected columns, debit sign, date format and the reported row number. AI failures can be handled by entering the receipt manually.

Receipt inbox (v0.3.0)

Choose Capture receipts to upload multiple files or take a photo. Save now and categorise later. Ollama can read uploaded receipts; results persist in the inbox. Review the merchant, date, AUD amount, workspace, category and use percentage before saving an expense. Suggestions use your reviewed merchant history. Matching transactions can be linked explicitly to avoid adding another expense. Unfiled receipts stay out of expense totals and tax-agent sharing. The updated invoice PDFs are attached to invoice emails automatically.
